# shortenTHATlink — Product Requirements Document

**Status:** MVP scope frozen — ready for implementation
**Stack:** Next.js, Drizzle ORM, PostgreSQL, better-auth, Vercel (hosting + Cron)

---

## 1. Overview

shortenTHATlink is a URL shortener that lets anyone create a short link instantly, with optional accounts for managing links and choosing custom aliases.

**Design principle:** short aliases are convenient identifiers, not a security boundary. Anyone who guesses or is given an alias can use it. Sensitive-link protection (passwords, single-use links, private visibility) is explicitly out of scope for this MVP and would be a separate future feature, not a side effect of alias length.

---

## 2. Goals (MVP)

- Anyone (anonymous or logged in) can shorten a URL and get a working redirect immediately.
- Logged-in users can view and manage the links they've created.
- Users can optionally convert a generated alias into a memorable custom alias.
- Expired links stop working immediately and are eventually purged from the database.

## 3. Non-Goals (MVP)

- Click analytics / tracking (no `clicks` table, no click counts).
- Alias history or redirect chains (old alias simply stops resolving on rename — no record kept).
- Private/password-protected/single-use links.
- Link editing beyond alias (e.g. changing destination URL after creation).
- Teams, org accounts, or shared link ownership.

---

## 4. Data Model

### `user` (owned by better-auth)

Not hand-authored — generated by the better-auth CLI (`npx @better-auth/cli generate`) alongside `session`, `account`, and `verification` tables. Do not hand-edit; regenerate when auth config changes. Core fields relevant to this app:

| Field                                                                                                                       | Type                   | Notes                                                                                        |
| --------------------------------------------------------------------------------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------- |
| `id`                                                                                                                        | text, PK               | Provider-agnostic ID (not a serial int) — this is why `Url.userId` is `text`, not `integer`. |
| `email`                                                                                                                     | text, unique, not null |                                                                                              |
| `createdAt`                                                                                                                 | timestamp, not null    |                                                                                              |
| `updatedAt`                                                                                                                 | timestamp, not null    |                                                                                              |
| ...plus additional columns better-auth generates depending on enabled auth methods (e.g. `emailVerified`, `name`, `image`). |                        |                                                                                              |

### `Url`

| Field           | Type                             | Notes                                                                                                                                                                                                  |
| --------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`            | serial, PK                       | Internal identity. Stable, never exposed publicly, never changes even if alias changes.                                                                                                                |
| `alias`         | varchar(52), unique, not null    | Public identifier used in the redirect path. Case-insensitive — normalized to lowercase on write and lookup.                                                                                           |
| `originalUrl`   | text, not null                   | Destination URL.                                                                                                                                                                                       |
| `isCustomAlias` | boolean, default false, not null | Provenance flag — was this alias user-chosen (and thus validated against custom-alias rules) vs. system-generated. Cannot be reliably derived from the alias string itself, so it's stored explicitly. |
| `userId`        | text, FK → user.id, nullable     | Null = anonymous link. `onDelete: cascade`. Type is `text` to match better-auth's generated `user.id`, not `integer`.                                                                                  |
| `expiresAt`     | timestamp, nullable              | Null = never expires.                                                                                                                                                                                  |
| `createdAt`     | timestamp, not null              |                                                                                                                                                                                                        |
| `updatedAt`     | timestamp, not null              | Updated whenever the row changes (primarily alias renames). Set on write, defaults to `createdAt` value at insert.                                                                                     |

**Indexes:** unique index on `alias`; index on `userId` (for "my links" queries); index on `expiresAt` (for the cron cleanup query).

No `clicks` table, no alias-history table. The database stores only the current state of each `Url` row.

## 5. Behavior & Rules

### Creation

- Anyone can create a short URL — no login required.
- Anonymous creations have `userId = null`.
- Logged-in creations attach the creator's `userId`.
- Default alias generation uses NanoID (9 characters, custom alphabet excluding visually ambiguous characters: `23456789abcdefghjkmnpqrstuvwxyz` — no `0`/`O`, `1`/`l`/`I`, no uppercase).
- On generated-alias collision (rare): retry generation up to 5 attempts, then fail with an explicit error rather than looping indefinitely.

### Custom aliases

- Any user (anonymous or logged in) may supply a custom alias at creation time, or a logged-in user may convert an existing generated alias to custom later.
- Validation rules:
  - 4–52 characters
  - Letters, numbers, hyphens only (`a-z0-9-` after lowercasing)
  - No `/`
  - Cannot start/end with a hyphen; no consecutive hyphens
  - Case-insensitive — normalized to lowercase before validation, storage, and lookup
  - Rejected if it matches the reserved-alias list
- On custom-alias collision: reject with a clear "alias already taken" error (no retry — the user picks a different value).

### Editing

- Only custom aliases are editable. Generated aliases must first be converted to custom (which is itself an edit) before further renaming.
- Renaming is destructive to the old identifier: the old alias stops resolving **immediately** upon change. There is no redirect chain, no grace period, and no history retained — the new alias becomes the sole public identifier for that `Url` row.
- Renaming updates `updatedAt` on the row.
- Only the owning user (`userId` match) may edit or delete a link. Anonymous links are not editable/deletable after creation (no owner to authorize the action) — acceptable for MVP.

### Redirect

- `GET /[alias]` looks up the row by lowercased alias.
- If no row matches → 404.
- If `expiresAt` is set and in the past → treat as not found (expiration is checked at redirect time, independent of whether the cron job has run yet — the row may still physically exist but must not redirect).
- Otherwise → redirect to `originalUrl`.

### Expiration & cleanup

- `expiresAt` is optional at creation; null means the link never expires.
- Expiration is enforced logically at redirect time regardless of deletion state (see above).
- A Vercel Cron job runs on a schedule and physically deletes rows where `expiresAt < now()`. This is cleanup/hygiene, not the enforcement mechanism — enforcement always happens at redirect time.

### Reserved aliases

- A maintained list of reserved words prevents custom aliases from colliding with application routes (e.g. `api`, `admin`, `dashboard`, `login`) and near-term reserved terms (e.g. `static`, `assets`).
- This list must be kept in sync with the app's actual route tree as new top-level routes are added — it is not auto-derived.

## 6. API Surface (MVP)

| Route               | Method | Purpose                                        | Auth                        |
| ------------------- | ------ | ---------------------------------------------- | --------------------------- |
| `/[alias]`          | GET    | Redirect to `originalUrl`, or 404/expired      | None                        |
| `/api/urls`         | POST   | Create a short URL (generated or custom alias) | Optional                    |
| `/api/urls`         | GET    | List the current user's URLs                   | Required                    |
| `/api/urls/[id]`    | PATCH  | Edit alias (custom only)                       | Required, must own row      |
| `/api/urls/[id]`    | DELETE | Delete a URL                                   | Required, must own row      |
| `/api/cron/cleanup` | DELETE | Purge expired rows (Vercel Cron target)        | Cron secret / internal only |

## 7. Open Questions / Deferred Decisions

These were deliberately deferred during scoping and should be revisited only if they become blocking during implementation — not resolved speculatively:

- Confirm Vercel Cron frequency/availability matches the current plan/tier before relying on it in production.
- Future "sensitive link" feature (password protection, single-use, private visibility) — explicitly out of scope, would be additive, not a redesign of the existing schema.
- Rate limiting on anonymous link creation (abuse prevention) — not yet designed.

---

## 8. Success Criteria (MVP done when)

- [ ] Anonymous and logged-in users can create short links via the API.
- [ ] Generated aliases are unique, collision-safe, and unguessable enough for casual use.
- [ ] Custom aliases pass all validation rules and reject collisions with a clear error.
- [ ] Redirect works and correctly blocks expired links.
- [ ] Logged-in users can list, rename (custom only), and delete their own links.
- [ ] Cron job deletes expired rows on schedule without affecting active links.
